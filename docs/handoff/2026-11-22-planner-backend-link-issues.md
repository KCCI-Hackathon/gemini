# 메인 화면 백엔드 · 에이전트 연결 — 남은 문제 (파트별)

> 2026-11-22 · 정리 : Jongeume (Claude Code 와 작업) · 브랜치 `agent/planner-backend-link`
> 설계 : `docs/superpowers/specs/2026-11-22-planner-backend-link-design.md` · 계획 : `docs/superpowers/plans/2026-11-22-planner-backend-link.md`

**한 줄 요약 : 새 메인 화면(Planner)에 백엔드 판정 · 중복수혜 · AI 계획을 연결한 MVP 다. 테스트는 통과하지만 독립 검증에서 시연을 막는 문제 2건(높음)이 나왔다. 아래 표대로 에이전트 · 판정 코드 · 프론트엔드 파트별로 이어서 고친다.**

## 1. 이번 브랜치에서 된 것

| 기능 | 상태 |
|---|---|
| 카드 판정 = 백엔드 자격 판정(`judgePolicy` 의 `personal`), 검증 배지(근거 확인 대기 등) 분리 | 됨 |
| 실제 수혜 충돌 · 부분 제한 · 질문을 백엔드 `evaluateRules` 결과로 표시 | 됨 |
| 담은 정책끼리 충돌을 백엔드 `planned_conflicts` 로 판정 → 비교 · 교체 | 됨 (실데이터에서는 시연 불가, 아래 판정 코드 J-7) |
| 개인 수혜 상태 입력 · 저장 · 에이전트 질문 답 · 이번 달 받은 금액 | 됨 (질문 흐름은 아래 J-1 로 막힘) |
| "예시로 둘러보기" = 실데이터 + 시연 인물 PERSONA_A | 됨 |
| 에이전트 패널 "나에게 맞는 경로 추천해줘" → `/api/plan`, 실패 시 규칙 추천 | 됨 (실제 AI 응답은 미확인) |
| 백엔드 판정 파일(`lib/judge/*`, `lib/data/*`, `lib/plan/*`, `scripts/overlap/*`, `data/*`) | 안 바뀜 |

확인 : 테스트 61개 파일 434개 통과 · `tsc --noEmit` 오류 0 · `npm run lint` 오류 0, 경고 1 (2026-11-22, 로컬)
독립 검증 : opus-critic (구현과 다른 실행 맥락). 브라우저 화면은 아무도 아직 눌러 보지 않았다.

## 2. 남은 문제 — 판정 코드

주로 `lib/planner/overlap-bridge.ts`, `lib/planner/catalog.ts`, `lib/planner/evaluate.ts` (새 화면의 서버 판정 — 백엔드 결과를 카드로 옮기는 곳)

| 번호 | 심각도 | 문제 | 재현 · 근거 | 고칠 방향 (제안) |
|---|---|---|---|---|
| J-1 | **높음** | 이번 달 지급액 질문이 답해도 계속 남는다. 시연 인물의 첫 질문("해당 월에 실제로 지급받은 금액은 얼마인가요?", 미혼청년 주거급여 분리지급 → 인천시 청년월세)이 이것이라 질문 흐름이 막힌다 | 답은 오늘 달(`2026-11`)로 저장되는데, "수료 후" 열은 그 시점 달(`2026-12`)의 지급액을 찾는다. 0원으로 답해도 같은 질문이 남는 것을 Claude 가 직접 재현 | 질문에 "어느 달" 을 실어 보내고(시점별 질문) 답을 그 달로 저장. 또는 금액 질문은 "현재" 시점 카드에서만 묻기. "안 받아요"(`eligible_unpaid`)는 금액 규칙을 닫지 못하므로 금액 질문에서는 빼거나 0원 입력으로 대신 |
| J-2 | 중간 | 이미 막힌 카드(마감 · 나이 조건 밖 · 접수 기간 불교차)에서도 질문을 모은다. 질문 8개 중 7개가 답해도 판정이 안 바뀌는 질문 | `evaluate.ts` 150-151줄이 막힌 구간의 `verdict.questions` 도 모은다 | 막히지 않은(담을 수 있는) 카드의 질문만 모은다 |
| J-3 | 중간 | 차단 사유가 두 번 나오고, 조사 메모 문장이 화면 사유에 그대로 나온다. 예 : "…전국·인천 안내에 같은 사유를 두 번 표시하지 않는다." 이 문장이 키워드 때문에 STATUS · RESIDENCE 코드로 잘못 분류되기도 한다 | `judgePolicy` 가 넣은 차단 사유 + 변환 사유가 함께 쌓임. 부분 제한 문구에 백엔드 `research_basis.conclusion` 이 붙어 옴 | 변환 사유와 겹치는 `judgePolicy` 차단 사유를 뺀다. 화면용 짧은 문구 칸을 백엔드 데이터에 따로 둘지 결정 |
| J-4 | 중간 | I2(부분 제한은 판정을 낮추지 않음) 테스트가 실제로 아무것도 입증하지 못한다 | 청년월세 카드가 변경 전 · 후 모두 `blocked`(접수 마감) 라 `blocked == blocked` 비교 | 막히지 않은 카드로 테스트를 바꾼다 (시연 지역에 맞는 정책을 찾거나 가상 Offering 사용) |
| J-5 | 낮음 | 조사 오류 : "국민취업지원제도**과**", "구직급여**과**" | `overlap-bridge.ts` 31줄 `${r.sourceName}과` 고정 | 받침 여부로 와/과 |
| J-6 | 낮음 | 지급이 끝난 경우(`ended`)로 막혀도 "현재 수혜 중인 …" 으로 나온다 | 같은 31줄 | 수혜 상태별 문구 |
| J-7 | 낮음 | 질문을 보여 줄지 백엔드 사유 문자열 5개와 비교해 정한다. 백엔드 문구가 바뀌면 질문이 조용히 "기관 확인 필요" 로 바뀐다 | `overlap-bridge.ts` 42-45줄 | 백엔드 `Restriction` 에 질문 종류(무엇이 모자란지)를 구조화된 칸으로 내보낼지 결정 |
| J-8 | 낮음 | 담은 정책끼리 충돌(I4)은 실데이터 시연 불가 — 해당 두 정책(재직청년 복지포인트 · 드림For 청년통장)이 모두 접수 마감 | 실데이터 평가 결과 `stageWindow = null` | 시연용으로 열려 있는 충돌 쌍을 찾거나 시연 인물 조정 |
| J-9 | 확인 필요 | `axes.time.value === "unmet"` → `blocked` 줄이 빠졌다. 설계 "기간 판정은 지금 계산 그대로" 와 어긋날 수 있음 | PERSONA_A 에서는 차단 수 665장으로 변화 관찰 안 됨 | 의도한 변경인지 확인 |

## 3. 남은 문제 — 프론트엔드

주로 `app/workspace/*`, `lib/planner/schema.ts`, `lib/planner/storage.ts`

| 번호 | 심각도 | 문제 | 재현 · 근거 | 고칠 방향 (제안) |
|---|---|---|---|---|
| F-1 | **높음** | 이 브랜치 전에 저장한 계획과 탭 초안을 못 연다 ("읽을 수 없는 계획") | 카드 스키마에 `verifyLabel` 이 필수(`z.string().nullable()`)로 들어감 — `lib/planner/schema.ts` 49줄. 옛 저장본에는 이 칸이 없다 | `.nullable().default(null)` 또는 optional. 옛 `SavedPlan` 전체를 넣는 회귀 테스트 추가 |
| F-2 | 중간 | "신청 가능" 카드는 앞면에 부분 제한 주의 사유("○○ 미지급")가 안 보이고 상세에만 보인다 | `PolicyCard.tsx` 는 `blocked` · `needs_check` 일 때만 `reasons[0]` 표시 | 신청 가능 카드에도 주의 사유 한 줄 (설계 6.3 "신청 가능 + 주의 사유") |
| F-3 | 중간 | 이번 달 받은 금액 칸의 달이 늘 오늘 달 | `Dialogs.tsx` 57줄 · `Agent.tsx` 52줄 — J-1 과 같이 고쳐야 함 | J-1 결정에 맞춰 달을 받는다 |
| F-4 | 낮음 | 프로필 폼 안내 "입력 정보는 외부 AI로 보내지 않아요" 가 실제와 다르다. 시연 인물일 때는 수혜 상태가 `/api/plan` 으로 간다 (판정에만 쓰임) | `Dialogs.tsx` 114줄 | 문구 수정 |
| F-5 | 낮음 | 린트 경고 1 | `Planner.tsx` 126줄 cleanup 안의 `planSeq.current` | ref 값을 effect 안 변수로 복사 |
| F-6 | 확인 필요 | 브라우저 화면 전체 미확인 — 검증 배지 위치, 수혜 입력 칸, 질문 카드, AI 추천 표시, 담기 · 저장 · 비교 · 교체 흐름, 모바일 폭 | — | 브라우저 QA |

## 4. 남은 문제 — 에이전트

주로 `lib/planner/plan-request.ts`, `lib/planner/commands.ts`, `app/workspace/Agent.tsx`, `lib/planner/fixtures.ts`

| 번호 | 심각도 | 문제 | 재현 · 근거 | 고칠 방향 (제안) |
|---|---|---|---|---|
| A-1 | 중간 | 화면에서 수료일을 바꾸면 AI 계획의 기준일이 화면과 어긋난다. 예 : 수료 2027-02-15, 취업 2027-06-20 → `employAfterMonths: 4` 로 보내지만 서버는 시연 원본 수료일 12/19 + 4개월 = 2027-04-19 를 취업일로 계산 | `canUseAi` 는 프로필만 보고 일정을 안 본다 (`plan-request.ts` 27줄) | 화면 수료일이 시연 원본과 다르면 규칙 추천으로 돌리거나, `/api/plan` 이 정확한 날짜를 받게 확장 (판정 코드 파트와 협의) |
| A-2 | 중간 | 에이전트 패널은 첫 질문 하나만 보여 준다. J-1 때문에 첫 질문이 안 넘어가 뒤 질문(청년도전지원사업 등)에 닿지 못한다 | `Agent.tsx` 52줄 `first` | J-1 수정 뒤 확인. 질문 건너뛰기 버튼 검토 |
| A-3 | 낮음 | 시연 예시 버튼 "취업을 2월 13일로 옮겨줘" 가 "몇 년의 일정인가요?" 되묻기로 바뀐다. 시연 인물 일정(`PERSONA_DEMO_EVENTS`)에 취업 예정이 없다 | 설계 6.1.1 "시나리오를 실제 정책으로 다시 짠다" 미구현 | 시연 시나리오(취업 예정일 포함)를 실제 정책으로 다시 짜고 예시 버튼 문구 맞추기 |
| A-4 | 확인 필요 | 실제 AI 응답(200 + plan)이 보드에 붙는 모습, 서버 `timedOut`, 클라이언트 60초 시간 초과, 429 | AI 꺼진 환경에서만 확인 (503 → 규칙 추천 정상) | AI 키가 있는 환경에서 시연 흐름 확인 |
| A-5 | 확인 필요 | "왜 제 기한은 더 빠른가요?" 예시 버튼이 실데이터에서 어떻게 답하는지 | 미확인 | 확인 |

## 5. 순서 제안

1. **J-1 + F-3 + A-2** (질문 흐름) 과 **F-1** (옛 저장본) — 시연을 막는 것부터
2. J-2 · J-3 · F-2 · A-1 — 화면에 틀린 내용이 보이는 것
3. 나머지 낮음 · 확인 필요

에이전트 최적화(응답 품질 · 속도 등)는 위 1~2 가 끝나 통합 설계대로 동작한 뒤에 한다.
