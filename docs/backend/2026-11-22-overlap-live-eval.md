## 적용한 개선

- **빠진 필드 재질문.** 3.5 Flash-Lite는 약 12,000자 묶음에서 정책을 통째로 건너뛰었고, 기존 완전성 검사는 받은 행만 검사해 이를 놓쳤다. 이제 모든 정책·필드에 조항 또는 `"kind":"none"` 행을 요구하고, 빠진 필드는 그 필드만 다시 묻는다. 기존에 거절된 조항이 있던 필드는 다시 물었을 때 실제 조항을 내야 완료로 인정한다. 추출 누락이 53건에서 9건으로 줄었다.
- **재검증 대체 모델.** 원인 미확인 429·5xx·응답 없음이 세 번 이어지면 해당 모델을 10분 쉬게 하고, HTTP 403·404 모델은 다음 한도 초기화까지 건너뛴다. `a4be03e1`과 `4dab4f91`에서 3 Flash의 연속 429 뒤 3.6 Flash로 넘어갔고, 3.6 Flash도 반례 3건을 기각했다.
- **같은 이름 정책 선택.** 청년내일저축계좌는 스냅샷에 24개, 국민취업지원제도는 3개 레코드가 있다. 모델이 고른 정책과 정식 명칭이 같은 레코드 중 B와 같은 시·도의 최신 레코드, 없으면 최신 중앙부처 레코드를 고른다. 둘 다 없으면 모델의 선택을 유지한다.
- **연결 후보 정리.** 같은 명칭의 지역 레코드가 후보를 채우지 않도록 명칭당 한 자리로 묶고 최대 8개를 보낸다. 연결 요청에 B의 정책명과 기관을 함께 보낸다. 연결 없음이 31건에서 13건으로 줄었다.
- **일반 명칭 연결 지시 철회.** `4dab4f91`에는 "일반 명칭이면 해당 사업을 고르라"는 지시가 있었다. 청년희망적금을 청년희망주택 임대료 지원에, 아이돌봄서비스를 일상돌봄 서비스 사업에 연결하는 등 연결하지 말아야 할 사례가 5건에서 10건으로 늘었다. 모델 연결은 전체 차단으로 확정되지 않지만 `/api/judge`에서 무관한 사업의 확인 필요 안내가 된다. 이 지시를 제거하고 "이름이 비슷하기만 한 다른 사업은 고르지 말라"로 바꿨다. 이 변경은 실호출로 다시 채점하지 않았다.

## 남은 과제

1. **조건 분류(25건).** 연결이 개선되자 조건 유형·매개변수가 정답과 다른 사례가 드러났다. 추출 지시의 조건 정의와 예시를 정답 표본으로 점검해야 한다.
2. **한 언급이 여러 사업을 가리키는 경우.** "주택도시기금 대출상품"은 정답에서 4개 사업, "국토부 또는 지자체 청년월세 지원사업"은 여러 지역 사업에 연결된다. 현재 연결은 언급 하나에 정책 하나만 지원한다.
3. **인용·언급 범위(42건).** 목록형 원문에서 인용을 항목 단위로 나누는 범위가 정답과 다르다.
4. **불완전 묶음(11/15).** 빠진 필드를 다시 물어도 응답하지 않는 필드가 남는다. 묶음 크기를 줄이면 요청 수가 늘어 Flash-Lite 한도와 함께 검토해야 한다.
5. **정답에 없는 새 쌍.** `4dab4f91`은 재검증 지지 341건을 냈지만 품질을 검토하지 않았다.

## 호출량과 한도

무료 등급에서 Flash 계열의 일일 한도는 모델당 20건이다. 새 방식의 한 번 실행은 추출 23~28건, 연결 11~18건(3.5 Flash-Lite), 재검증 15~24건(Flash)이었다. 같은 프롬프트의 저장 응답은 재사용하므로 `4dab4f91`의 실제 호출은 연결 18건과 재검증 5건이었다. Flash-Lite는 HTTP 503이 자주 발생해 연결 단계가 수 분씩 지연됐다.

## 재현

```bash
npm run overlap:agent -- --live                  # 새 실행
npm run overlap:agent -- --replay --run-id <ID>  # 같은 코드의 저장 응답으로 재채점
npm run db:build -- --research-only
npm run db:export
npm run db:verify
```

추출·연결 프롬프트가 바뀌면 이전 실행을 현재 코드로 재생할 수 없다. 이전 실행은 해당 커밋의 작업 폴더에서 재생한다.
